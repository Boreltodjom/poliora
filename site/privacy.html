Help center / Privacy & data

Privacy boundary

Your workspace is not our analytics.

Updated November 26, 2026. This notice distinguishes the local desktop app, the public website and information you voluntarily share with support.

The desktop app

Poliora runs its dashboard on your computer, bound to 127.0.0.1. Workspace files are stored in a local .poliora directory. The desktop installer uses the operating system's per-user application-data location; the CLI uses the workspace you select.

No Poliora account is required. The app has no automatic upload of product usage, local logs or workspace data to a Poliora analytics service. We cannot see who installed or used the app from a website visit alone.

Usage metadata you approve

Supported sources may provide provider and model identifiers, timestamps, token totals, recorded costs, plan or quota information, request status and labels. Local history scanning previews supported Codex and Claude Code usage fields before you approve an import. A launcher availability check is a separate operation and is not evidence of spend.

Cost analysis does not require prompts, model replies, source code, private chats or credentials. Do not put sensitive content into project, customer or workflow labels. Quota fields may be missing or out of date, and equivalent API value is an estimate, not an invoice.

Network activity

Optional provider-backed actions, such as model discovery, contact the provider you choose. API wrappers still contact the provider used by your application. Download links contact GitHub, and the optional Python installation uses PyPI. These services have their own policies.

Provider credentials remain in your local configuration or environment; they are not required for reviewing supported local history and should never be included in feedback.

The public website

Cloudflare hosts this website and processes requests needed to deliver and secure it. Cloudflare Web Analytics, when enabled, measures aggregate website visits and performance, with dimensions such as page, referrer, device and country. It is separate from the desktop app and does not receive your Poliora workspace, token history, prompts or provider keys.

We do not add advertising pixels, session replay or cross-site tracking to this website. The support form does not save drafts to browser storage, and form contents are not sent to an analytics endpoint. Read about Cloudflare Web Analytics.

Feedback is a deliberate action

The feedback form builds a draft in your browser. Previewing or copying it does not send it to us. Opening an email draft passes its contents to your configured email application. Opening a GitHub draft passes its contents to GitHub; the issue is public if you submit it. Never include confidential information in a GitHub issue.

If you send an email, we receive its contents, your email address and any attachments you choose to send. If you submit an issue, GitHub associates it with your GitHub account. We use this information to investigate feedback and respond. No app logs or diagnostics are attached automatically.

Your choices

You control your local workspace, exports and backups. Review reports before sharing them; they may contain customer labels, model usage or costs. Use Feedback & support to ask about information you have voluntarily sent us. We retain support correspondence as needed to handle the request and related follow-up; do not send sensitive data that is not needed.

Security reports

Do not post vulnerabilities or credentials in public feedback. Follow the security reporting policy.
